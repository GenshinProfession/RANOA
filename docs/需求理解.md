## 需求概述

构建一个以 Pi Agent 为执行核心、以 Pi Web 交互体验为参考的企业级 AI Harness 工作台。系统既保留会话、工具调用、上下文占用、缓存命中和 Token 消耗的透明度，也提供跨项目的组织记忆、统一用量与计费治理，以及可扩展的内部游戏/应用中心。首期目标不是一次完成全部平台能力，而是先验证“统一 Agent 工作台 + 全局记忆 + 可核算用量”这一核心闭环。

## 目标用户与场景

- 个人开发者：在多个项目之间复用规范、偏好和工作记忆。
- 公司员工：通过统一入口创建和管理 Agent 任务，查看任务进度和成本。
- 管理员/财务：按用户、团队、项目、供应商和模型核对额度、用量与账单。
- 内部开发者：开发、测试并发布可在工作台内运行的轻量游戏或互动应用。

## 功能需求

### P0 - 必须实现

- [ ] Agent 工作台：提供类似 Codex 的项目/任务侧边栏、会话列表、实时输入输出、工具调用和任务状态展示。
- [ ] 上下文治理：展示当前上下文占用、输入/输出 Token、缓存读取/写入、压缩记录和模型限制。
- [ ] 分层记忆：支持系统级、组织级、项目级、用户级和会话级记忆，并定义明确的覆盖顺序和注入策略。
- [ ] 记忆管理：记忆可查看、搜索、编辑、禁用、标记来源、设置有效期，并记录审计历史；不得让模型在无审计的情况下静默改写强制规范。
- [ ] 统一模型网关：通过统一适配层连接不同供应商和模型，规范请求、响应、错误、流式事件和 Token 用量字段。
- [ ] 用量账本：逐次记录供应商、模型、用户、项目、会话、请求、输入/输出/缓存 Token、估算费用和供应商返回的原始计量数据。
- [ ] 任务进度：在全局区域展示正在运行、等待输入、失败和已完成的任务及其可验证进度。
- [ ] 身份与权限：至少区分管理员、普通用户和内部应用开发者，数据按组织、项目和用户隔离。

### P1 - 重要功能

- [ ] 供应商额度查询：在供应商提供官方余额/配额/用量 API 时接入并定时同步；无官方接口时明确标记为估算或人工录入，不伪装成真实余额。
- [ ] 账单对账：将本地请求账本与供应商账单/用量报表对账，保留差异及计价规则版本。
- [ ] 预算与告警：支持团队、项目、用户和供应商维度的预算、软限额、硬限额与异常消耗告警。
- [ ] 多人协作：共享任务状态、任务产物和允许共享的记忆；支持权限控制和审计。
- [ ] 游戏中心：工作过程中可打开轻量游戏，支持多人房间、邀请和状态同步，并与 Agent 任务运行状态解耦。
- [ ] 内部游戏发布：支持提交、审核、版本化发布、灰度、下架和权限范围控制。

### P2 - 可选功能

- [ ] 记忆建议：模型可以提出新增或修改记忆的建议，由用户或管理员确认后生效。
- [ ] 语义检索：对非强制型长期记忆做向量检索，只注入与当前任务相关的内容。
- [ ] 成本路由：根据价格、上下文长度、质量和余额选择模型，但必须允许用户锁定模型。
- [ ] 激励机制：将任务完成、协作或游戏成就形成组织内积分，但不得影响真实计费账本。
- [ ] 第三方插件生态：允许非游戏类内部工具以同一应用协议接入工作台。

## 非功能需求

- 性能：会话流式事件应近实时展示；账本写入不能阻塞模型输出；余额同步和账单对账采用异步任务。
- 安全：API Key 只保存在服务端密钥库；游戏/应用运行在权限受限的沙箱中；所有组织记忆变更和计费事件可审计。
- 一致性：请求级 Token 数据采用不可变账本；价格规则带版本和生效时间，历史费用可复算。
- 可用性：Agent 运行、计费同步和游戏服务相互隔离，单个供应商或游戏故障不能拖垮主工作台。
- 可扩展性：供应商、记忆策略和内部应用均通过稳定接口扩展，避免直接耦合到 UI。
- 合规：共享记忆和会话前必须明确数据范围；支持删除、导出和保留期限策略。

## 边界与约束

- 首期不承诺所有厂商都能查询“真实剩余 Token”。很多供应商只提供余额、消费额、速率限制或延迟账单，能力取决于官方 API。
- 供应商 Token 统计、供应商最终账单和本地估算是三个不同口径，界面必须分别展示。
- 游戏中心不是首期核心闭环，首期只预留应用容器、任务状态入口和权限模型。
- Pi Web 当前是面向本机的 Next.js 工作台，只有 Basic Auth 和本地文件会话模型；企业多用户、组织权限、集中计费需要新增后端服务和数据库。
- 当前全局安装包 `@agegr/pi-web@0.8.7` 使用 MIT 许可证，技术上可以二次开发；应从其源码仓库建立 fork，不应直接修改全局 npm 构建产物。
- Pi 执行核心当前来自 `@earendil-works/pi-* 0.84.0`，二开时应通过适配层封装，避免未来 Pi fork 或版本升级影响平台业务。

## 核心验收标准

### Agent 工作台

- Given 用户已登录并拥有项目权限，When 创建一个 Agent 任务，Then 侧边栏出现任务并实时展示运行状态、输出、工具调用和最终结果。

### 分层记忆

- Given 组织规范、项目规范和用户偏好同时存在，When 启动新会话，Then 系统按可解释的优先级组装上下文，并展示本次实际注入了哪些记忆及其来源。

### 用量账本

- Given 一次模型请求完成，When 查看请求详情，Then 可看到供应商原始用量、平台规范化 Token、缓存 Token、价格版本和本次费用；数据可按项目和用户聚合。

### 供应商额度

- Given 供应商提供官方查询接口，When 系统执行同步，Then 展示官方数据及同步时间；Given 不提供接口，Then 页面明确显示“不支持官方查询”并区分本地估算。

### 任务进度

- Given 多个任务并行运行，When 用户查看全局进度区，Then 能区分运行、等待确认、失败和完成状态，并可跳转到对应任务。

### 游戏中心

- Given 用户正在运行 Agent 任务，When 打开一个已审核游戏，Then 游戏可以独立运行或加入多人房间，且退出/崩溃不会影响 Agent 任务和计费账本。

## 关键假设与待确认项

- 默认采用企业内部部署，而不是面向公网的消费级 SaaS。
- “全局记忆”既包含强制规范，也包含可检索经验，两者必须采用不同治理方式。
- “游戏”指工作台内可共享、可多人参与的轻量 Web 应用；若目标是云游戏或大型实时游戏，架构和投入会完全不同。
- 需要进一步确认首批供应商、预计用户规模、部署环境、是否需要人民币账单/发票口径，以及游戏与工作任务之间预期的业务关系。

# Harness 开发环境隔离

本仓库的二次开发实例必须与本机已安装的 Pi Web 分开运行。默认隔离规则如下：

| 项目 | 现有 Pi Web | Harness 开发实例 |
| --- | --- | --- |
| 端口 | `30141` | `31141` |
| Agent 数据 | `~/.pi/agent` | `<repo>/.pi-harness-dev/agent` |
| 启动方式 | 全局 `pi-web` | `npm run dev:harness` |

启动开发实例：

```powershell
npm run dev:harness
```

浏览器访问 `http://127.0.0.1:31141`。

启动器会将 `PI_CODING_AGENT_DIR` 指向仓库内被 Git 忽略的隔离目录，并拒绝使用默认端口 `30141` 或现有数据目录 `~/.pi/agent`。不要把真实 API Key 或现有会话长期复制到隔离目录；受控验收如需临时凭据，必须获得明确授权，并在测试后清空配置、扫描工作区确认无 Token 残留。数据迁移将在独立阶段设计、备份和验收。

如需安全地覆盖开发端口或隔离目录，可在当前 PowerShell 会话中设置：

```powershell
$env:PI_HARNESS_PORT = "32141"
$env:PI_HARNESS_AGENT_DIR = "C:\\path\\to\\isolated-agent"
npm run dev:harness
```

`PI_HARNESS_AGENT_DIR` 不得指向 `C:\Users\<user>\.pi\agent`，也不得使用其父目录或子目录。

在隔离实例已经配置测试供应商后，可运行真实链路冒烟脚本：

```powershell
$env:PI_HARNESS_E2E_PROVIDER = "测试供应商名"
$env:PI_HARNESS_E2E_MODEL = "测试模型 ID"
$env:PI_HARNESS_E2E_CWD = (Get-Location).Path
npm run smoke:harness
```

脚本会验证创建会话、SSE 连接、运行中断线重连、`read` 工具调用、最终回复和 Token 用量。脚本本身不读取、打印或保存 API Key。
